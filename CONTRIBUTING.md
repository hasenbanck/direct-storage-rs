# Contributing to `direct-storage-rs`

## Regenerate `DirectStorage` metadata and bindings

The bindings are generated by [`api_gen/`](api_gen/) in a single step: the `dstorage.h` and `dstorageerr.h` headers from the `Microsoft.Direct3D.DirectStorage` NuGet package are parsed with [`windows-clang`](https://github.com/microsoft/windows-rs/blob/master/docs/crates/windows-clang.md) into reviewable RDL under [`metadata/`](metadata/), compiled to a `.winmd`, and projected to Rust with [`windows-bindgen`](https://github.com/microsoft/windows-rs/blob/master/docs/crates/windows-bindgen.md) into [`src/bindings.rs`](src/bindings.rs).  The pinned libclang, Windows SDK and DirectStorage NuGet packages are downloaded automatically.

D3D12 types referenced by DirectStorage (`ID3D12Device`, `ID3D12Resource`, `D3D12_BOX`, ...) are not generated, but imported from [`d3d12-agility`](https://github.com/Traverse-Research/d3d12-agility-rs) so that they are interchangeable with the rest of the D3D12 ecosystem; see `FROM_D3D12_AGILITY` in [`api_gen/src/main.rs`](api_gen/src/main.rs).

When the `windows-*` crates or the `DirectStorage` NuGet package are updated, or when changes are made to the bindings configuration, regenerate the bindings with:

```sh
cargo r -p api_gen
```

This also runs as a CI job, which fails when the committed RDL or Rust code differs from the generated output.
